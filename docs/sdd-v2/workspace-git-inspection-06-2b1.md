# Stage 06-2B1: read-only Git observation

Status: read-only Git **semantic** adapter (`src/workspace-git/`). This is not the final WorkspaceFingerprint, a retained Git snapshot, a source freshness guarantee across both adapters, or preparation authority. The [WorkspaceProvider contract](workspace-contract.md), [06-1 pure domain](workspace-domain-06-1.md) and [06-2A local inspection](workspace-local-inspection-06-2a.md) remain normative.

## Trust and invocation

The caller supplies the exact canonical Linux execution root, control-project and project IDs, registered-root-association digest and strict v2 capture policy. Registration/authentication and control-root source inspection remain the caller's responsibility. The adapter requires an actual `.git` directory or linked-worktree `.git` file at **that** root; `GIT_CEILING_DIRECTORIES` prevents discovery through ancestors, and `--show-toplevel` must equal the supplied root. A marker-less bare repository is diagnosed separately. No source tree is cloned, written or scanned for bytes. Git is trusted host software operating on host-controlled repository metadata; an untrusted repository/config capable of influencing Git's own parser is not a sandboxed input. Git executable is `/usr/bin/git` on certified Linux. PATH, home and global/system Git config are not inherited. This is not kernel `openat2` confinement of the Git subprocess, and hostile same-UID pathname swaps remain outside the guarantee.

The narrow runner accepts only `rev-parse`, `symbolic-ref`, `cat-file`, `config`, `ls-files`, `diff-index` and `status`. It uses argv, explicit cwd, `shell:false`, ignored stdin, a sanitized environment, `LC_ALL=C`, `GIT_OPTIONAL_LOCKS=0`, `GIT_NO_LAZY_FETCH=1`, `GIT_NO_REPLACE_OBJECTS=1`, `GIT_TERMINAL_PROMPT=0`, `GIT_ASKPASS=/bin/false`, `GIT_PAGER=cat`, `GIT_LFS_SKIP_SMUDGE=1`, no inherited Git config env, and command-line overrides for fsmonitor, untracked-cache, split-index, color, path quoting, external diff and pager. Local config enabling clean/process/smudge filters, external diff drivers or textconv is rejected **before** status; sparse, partial, shared/split index, skip-worktree and assume-unchanged are also rejected. None of these commands runs hooks or mutating worktree/index operations; `status` is run with optional locks disabled so incidental index refresh cannot write the index. A test checks index bytes, mtime/ctime, HEAD, branch ref, config and worktree bytes before and after inspection. OS atime may change. Do not infer this guarantee for the historical `src/git/status.ts` helper.

Each command has a 10 s timeout, 32 MiB stdout and 64 KiB stderr limit; index is streamed through SHA-256 under a 64 MiB limit. Up to 250,000 distinct paths, 250,000 untracked and ignored entries each, 10,000 gitlinks, and 4,096 UTF-8 bytes per logical path are allowed (the global distinct-path limit applies across categories). Limits are operational, not exemptions: exceeding one fails, never yields a truncated observation. Output is bounded at the pipe and decoded from NUL records. An injected test reader is host/test instrumentation only, not a generic execution backend.

## Identity and HEAD

Git has **no reliable immutable repository UUID** shared by arbitrary clones. V1 `RepositoryIdentity` is therefore a *provisional, locally verified physical association*, not proof of portable repository continuity or registry authority: SHA-256 of a versioned subject containing canonical Git **common directory** path, its device/inode and object format, encoded in the `repository_` namespace. It is neither just the absolute execution path nor just HEAD. Two linked worktrees share this association. It changes if the common directory is replaced or moved; a clone with the same commit is not the same registered repository. An adversary coherently replacing metadata is not defeated by this ID; registration and future store provenance must verify continuity. The separate worktree association SHA-256 binds repository association, canonical per-worktree Git directory path and its device/inode. It is **not** `WorkspaceId` or incarnation; those must be minted and registered separately. Inodes/paths are association inputs, not a shortcut for content equality or a source of standalone lifecycle authority. Operational root, gitdir and common-dir paths, raw index byte hash and times are audit data; index stat/bytes are race anchors and do not enter the semantic Git state hash directly.

HEAD is attached with exact `refs/heads/...` and full resolved commit, detached with full commit, or unborn with attached ref but **no invented base**. An invalid/corrupt HEAD fails with `workspace-git-head-invalid`; unborn can be returned as an explicitly unsupported read-only observation. Bare repositories and non-root nested executions are distinct diagnostics. A valid base is a full 40-character SHA-1 or 64-character SHA-256 Git commit OID under explicit object format, checked with `cat-file -t` and no lazy fetch; it is not an Aira SHA-256 content hash. This read-only check does not certify Git object closure or protect against known SHA-1 collision limitations. Attached branch ref is observed Git semantic state but is never substituted for the base commit. Base and HEAD drift across the observation fail.

## Versioned observation and classifications

`aira.dev/workspace-git-inspection/v1` hashes its version-tagged canonical policy subject. It pins Git porcelain v2 with `-z --no-renames` for tracked worktree changes, `diff-index --cached --raw -z --no-renames --no-ext-diff --no-textconv` against the exact base commit for staged changes (porcelain omits some gitlinks with submodule suppression), index stage-0 `ls-files --stage -z` and `ls-files -v -z` (flag safety), individual-file `ls-files --others -z --exclude-standard` and `--ignored --exclude-standard`, explicit include-ignored policy, rejects for sparse/partial/submodules/nested repositories and the limits above. The capture-policy hash also binds each observation. Heuristic rename/copy detection is intentionally **off**: deletion plus addition are distinct path changes; `GitChange` reserves rename/copy fields for a future protocol. Status records carry separate index and tracked worktree `XY` changes, HEAD/index OIDs and modes, and a path may have both changes. Git mode `100644`, `100755`, `120000`, `160000` is recognized; symlink/type/mode transitions and deletions are distinguished. Git status may internally compare file content for dirty detection; the adapter does not hash worktree files or claim their byte identity. Stage-0 index OIDs are Git blob identities, not measured Aira content hashes. Conflict stages, intent-to-add zero-OID entries, skip-worktree and assume-unchanged are unsupported.

Ignored files, including those under ignored directories, are enumerated individually, as are untracked files. This can be expensive: hit a bound and fail rather than silently omit dependencies. Git's untracked/ignored classification is not the complete local tree: empty directories, symlink targets and exact regular-file bytes belong to 06-2A. Additional declared provider-cache exclusions are those of the strict v2 capture policy; no `.gitignore`-based exemption is implied for ignored files. Both `.git/**` and **all top-level `.aira/**`** are excluded from fingerprint-facing Git entries. Tracked `.aira/**` path names can be found in the separate audit `tracked_aira`, but do not affect the semantic Git hash. Nested `.git` and untracked nested repositories fail; declared gitlinks (including a gitlink staged for deletion from HEAD) and `.gitmodules` (even an inert file, conservatively) fail as submodule-unsupported. Neither a submodule nor an external filter is invoked recursively. Git LFS is not fetched or interpreted.

Paths use fatal UTF-8 decoding of NUL records, 06-2A's `exactPathSchema`/`validLogicalPath`/alias grammar, exact spelling, code-unit ordering and explicit rejection of controls (including newline), traversal, absolute paths, invalid UTF-8, wildcards, case/Unicode aliases and exclusion aliases. No human-quoted or newline-delimited paths are parsed. A file Git can name but Aira v2 cannot represent fails; the grammar is **not** broadened implicitly. A status change in a name under `.aira` cannot reintroduce control material.

`GitObservation` has a versioned subject, Aira canonical-JSON/SHA-256 hash, and separate audit envelope. Its subject binds control/project/root-association IDs, repository/worktree association, format, HEAD/base, complete index stage-0 inventory, separate staged/tracked changes, untracked/ignored sets, submodule records, exclusions and policy hashes. It includes no worktree bytes, no local tree digest, and no WorkspaceFingerprint. `gitOverlayDescriptor` hashes the separate Git path classifications and exclusions, not full reproducible overlay bytes. `gitSourceObservation` builds the valid 06-1 source/base/overlay shape but sets source consistency to **unknown**, as Git-only best-effort inspection cannot prove a stable source capture interval. The provisional 06-1 source ID in this projection binds Git classifications, **not** the exact changed worktree file bytes: two different dirty file contents with the same Git status can project to the same unknown-consistency source ID. It must never be treated as an exact reviewed source or used as a preparation precondition. 06-2B2 must build the byte-complete source observation using 06-2A before setting stable/eligible provenance. This is an exposed 06-1 versus 06-2B1 incompleteness, not an implicit relaxation of the master source contract. It does not claim overlay reproduction, registration or preparation eligibility. `gitDirtyPolicyIssues` evaluates caller intent without changing observation: require-clean checks every covered dirty category, base-only preserves the reviewed overlay and rejects dirty in-place use, include-observed-overlay is only a candidate pending 06-2B2 closure.

## Coherence and freshness

Capture uses HEAD, object format, gitdir/common/root/marker stat, and **stream-hashed raw index bytes and stat** as first/last anchors. Git path classifications and index flags are collected **twice** and compared; config hazards and `.gitmodules` are checked at both ends. HEAD drift, root/gitdir replacement or classification drift fails unstable; index change/replacement fails `workspace-git-index-changed`. Raw index bytes are used only for operational race detection; semantic identity uses stage-0 mode/OID entries and change records. The algorithm is a bounded, best-effort before/after protocol, **not** an atomic snapshot or a proof of uninterrupted quiescence (including write/revert between checks). `compareGitObservations` validates exact subjects/hashes, ignores audit timing, and distinguishes project, repository, worktree, HEAD/base, index, tracked, untracked, ignored, submodule and policy changes. It is a Git source freshness comparison, not a 06-2A tree comparison or a verification-stability claim.

Structured diagnostics cover not-repository, root mismatch, bare, unborn, invalid HEAD, sparse, partial, submodule/nested, conflicts, unsafe path, command failure, stdout/stderr/path bound, timeout, state/index drift and policy incompatibility. Failure has no complete observation; explicit unsupported unborn/submodule observations can carry a subject but must not pass preparation. No filesystem byte hashing is duplicated; [06-2B2](workspace-capture-06-2b2.md) reconciles these classifications (including staged deletions and ignored/untracked files) with a compatible independently captured 06-2A `LocalTreeObservation` and the exact handle/source contract **before** constructing a complete v2 WorkspaceFingerprint. No WorkspaceStore, worktree creation, snapshot retention, worker, CLI or commit is part of this slice.
